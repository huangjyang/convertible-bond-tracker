**踩坑 (经验):**
1. macOS 26 launchctl 在 AI sandbox session 下 `bootstrap` / `load` 都报 Error 5 (I/O error), `crontab` 也被拒 (`Operation not permitted`)。
   解决: 重新登录一次 macOS 后 launchd 自动扫描 `~/Library/LaunchAgents/` 加载 plist; 或用户在 Terminal.app 跑 `bash ~/.kzzt-fetch/install.sh`。

4. Documents/ 目录权限 drwx------, 但 fetch_daily.py 用 `__file__` 定位 BASE, 所以 wrapper 必须 `cd` 到原项目目录再 exec python, 否则数据写到错误位置 (我犯过一次: 写到 `~/.kzzt-fetch/data/` 而不是项目 `data/`)。

## 榜单变迁页增加"今日新闻" (index.html)

- 需求: 在"榜单变迁"tab 的**新进榜单**里, 为每个新进转债显示当天相关新闻(若有)。
- 数据: `DAY.bonds[i].news` (数组, 每条含 date/title/media/url), 但 `changes.new_in` 里只有 code/name/rank/chg/turnover_yi **没有 news**。
- 实现: 新增 `newsFor(code)` 从 `DAY.bonds` 按 code 反查 bond 再取 news; 只显示**强相关**新闻(标题命中转债名/正股名), 过滤泛资讯(如"深沪北百元股数量","XX基金半年报"等)。最多 2 条, 无则留空。
- 关键: fetch_daily.py 抓新闻时在返回前 `r.pop("_s", None)` **把强相关标记丢了**, 所以前端只能用标题含转债名/正股名来近似判断强相关。
- 样式: `.newnews`(flex-basis:100% 换行到 li 第二行) + `.list li` 加 `flex-wrap:wrap`。新闻可点击打开原链接, 用 `event.stopPropagation()` 避免触发整行 openBond。

## 修复: "个券历史"页K线缺今天 (app.py bug)

- 现象: 个券历史页"近90日走势"K线最后一根停在 09-04, 没有今天(09-07)。
- **根因**: app.py `_rebuild_cache()` 里
  `last = hist[0]["date"]` 取的是 bond_hist[code] 的**首元素**,
  而 bond_hist[code] 是按日期**升序** append 的(先 09-04 后 09-07),
  所以 hist[0]=09-04(最旧在榜日), 导致历史页 meta.kline 取的是 09-04 快照的K线(15根, 缺今天)。
- **修复**: 改成 `last = hist[-1]["date"]`(最近在榜日), 历史页K线即取最新快照(16根, 含09-07)。
- 详情弹窗 mKline 用内存里 DAY.bonds 的 kline_90d(含今天), 一直正常; 只影响个券历史页 bkKline(用 meta.kline)。
- 需重启 app.py 才生效。

## 重启 app.py 的坑 (重要)

- 在 AI sandbox 里用 `nohup python3 app.py &` 启动长驻服务, **Bash 命令一结束进程就被沙箱回收**(端口变空)。
- 正确姿势: 用 Bash 工具 `run_in_background=true` 启动, 以 task_id 托管长驻进程。
- app.py 当前以后台任务 `pEwQ8f` 运行, 端口 8734 OK。
- 沙箱里 curl 本地 127.0.0.1:8734 会走 HTTP 代理报 502 (Connection refused), 需加 `--noproxy '*'` 或用 python urllib 直接测。

## 定时任务改为"刷新页面时触发" (用户要求, 已取消 launchd)

- 已删除: `~/Library/LaunchAgents/com.workbuddy.kzzt-fetch.plist` + `~/.kzzt-fetch/` 整个目录(wrapper/run.sh/install.sh/副本)。launchd 任务彻底清除。
- 新机制: 页面加载 → 前端 fetch `/api/refresh` → app.py 按需后台跑 fetch_daily.py → 前端轮询 `/api/refresh/status` → 完成后自动 reload。

**app.py 改动:**
- 新增 `import subprocess, sys, from datetime import datetime`
- 新增全局 `_fetch` 状态 + `_fetch_lock` + `_run_fetch(force)`(后台线程 subprocess 跑脚本) + `maybe_fetch(force)`。
- `maybe_fetch` 节流(返回 skipped/started/running): ① 正在跑→running ② 本次进程已抓过今天→skipped ③ data/ 已有今天快照→skipped ④ 周六日→skipped ⑤ 否则后台抓。
  - 周末跳过的理由: fetch_daily.py 是先打 2 个网络请求(全市场列表+指数分时)才判断交易日, 周末每次刷新都会白跑网络请求, 所以 app 层先拦掉。
- 端点: `/api/refresh`(force=1 强制) 和 `/api/refresh/status`。
- do_GET 里加 `raw_path = self.path` 用于解析 force 参数。

**index.html 改动:**
- header 加 `#forceFetch` 按钮(↻ 强制更新) + `#fetchInfo` 状态 span。
- 新增 `triggerRefresh(force)` / `startPoll()`; `loadDates()` 末尾调 `triggerRefresh(false)`。
- `_refreshChecked` 保证每次页面加载只自动触发一次(避免 loadDates 重入循环)。

**注意:** app.py 源码改动后必须重启才生效(`_rebuild_cache` 只在请求时按 mtime 判断, 不重载代码)。当前以后台任务 rsMEQp 运行(PID 74064)。
实测: force 抓取端到端 40 秒跑完, 20/20 完成, 数据正常。
